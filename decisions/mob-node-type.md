# Mobs: a `mob` node type, reusing the `located_in` edge

Maps' zone dossier (issue #28) shipped a Bestiary section against fabricated placeholder data, since the graph had no mob/creature data or node type at all. Oasis of Marr is the first zone with real mob nodes, sourced directly from eqlwiki.com's own Oasis of Marr page (creature list with level/level-range per entry).

Fix: a `mob` node type — `{ id, label, minLevel?, maxLevel? }`, same optional-bound shape `QuestSummary`/`QuestGroupSummary` already use for level gating, not a single `level` field, since eqlwiki.com mostly reports mobs as a level *range* ("Sand Giant: 33-37") rather than one number. A handful of named/unique mobs (Cazel, Hatar, Lockjaw) have a single wiki-stated level; those are stored as `minLevel === maxLevel`, not a separate scalar field, so every reader of a mob node checks the same two fields regardless of which kind it is.

`mob --located_in--> zone` reuses the exact edge type `npc`/`quest` already use for the same relationship (see `decisions/edge-semantics.md`) — no new edge type, disambiguated by the source node's own `type`, same precedent as everything else `located_in` already covers.

Id convention: `mob:<zone-slug>:<mob-slug>` (e.g. `mob:oasis-of-marr:cistern-asp`), matching `vendor:<zone-slug>:<npc-slug>`'s own zone-namespacing — a same-named creature in a different zone (eqlwiki.com reuses generic names like "Ghoul" and "Orc Priest" across many zones) gets its own node per zone rather than one shared node with multiple `located_in` edges, since level/difficulty for a given creature name can vary by zone and there's no single wiki page per creature to point both zone instances at (unlike quests, which do have `wiki_title` mapping to one shared page — see `decisions/wiki-links-per-entity-vs-shared-page.md`).

Only mobs with an eqlwiki.com-stated level made it into migration 060 — the wiki also lists several Oasis of Marr creatures with no level given at all (Dune Tarantulas, Dry Bone Skeletons, etc.); those aren't modeled since there's nothing to verify a level against, consistent with this repo's sourced-facts-only policy (`decisions/spell-icons-real-client-art-exception.md` is the one deliberate exception, and this isn't it).

"Stated level" isn't limited to the NPC table, though — migration 060 read only the table and, on that basis, excluded "generic Orc Warriors" as unleveled. They aren't: the same page's prose "Orc Highway" section states an approximate level band for both ("a orc warrior" ~20th, "[An Orc Warrior]" mid-teens), just not as a table row. Migration 091 added both as narrow ranges (19–21, 13–16) built around that wording. The lesson: check a zone page's prose sections, not just its NPC table, before excluding a creature as unleveled.

A stated level alone isn't sufficient, though: eqlwiki.com's per-zone "NPC table" is one shared table for every NPC in the zone, hostile or not — Oasis of Marr's own table mixes real creatures with "Qeynos Citizen" innkeeps/merchants and a Brell Serilis Symbol quest giver (Taldrik Stumpystout), all of which have a listed level too. Each row was checked against the page's own supporting text (spawn coordinates and loot for a real mob; "carries a fishing pole, for [quest]"-style notes for an NPC) before inclusion, not just presence in the table — see migration 060's own comment for the excluded names.

Out of scope, deliberately: loot/drop data (`decisions/quest-reward-modeling.md`'s item nodes exist, but nothing links a mob to what it drops yet), and any danger/threat rating beyond min/maxLevel — an earlier prototype pass tagged mobs with a threat tier (skittish/wary/aggressive/deadly) purely as placeholder UI polish, and it was cut for implying a real signal the data didn't back. If threat/danger modeling is wanted later, source it for real rather than reintroducing an invented tier.
