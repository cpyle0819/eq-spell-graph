# Messy bestiary categories: query eqlwiki's MediaWiki API, don't hand-check every page

Migrations 145-149/152/154/156's bestiary method (see `decisions/mob-node-type.md`) sources a zone's creature list from every page under `Category:<Zone>` that carries the wiki's `{{Namedmobpage}}` combat-stats template — established because a zone's own "Types of Monsters" prose list has no per-creature level data, only names. That method assumes the category is small and mostly creatures. It breaks down for a zone like Chardok, whose `Category:Chardok` mixes 287 pages of items, quests, and mobs with no way to tell them apart except opening each one — not worth doing by hand (see issue #36; Chardok was skipped for this reason in the Burning Wood/Innothule Swamp/Frontier Mountains batch).

**Fix:** hit eqlwiki.com's raw MediaWiki API (`/api.php`), not the rendered page through `WebFetch`'s summarizer. One request tells you, for every page in the category, which templates it transcludes — the exact signal the hand-check method was already looking for, just sourced mechanically for the whole category at once:

```
https://eqlwiki.com/api.php?action=query&generator=categorymembers&gcmtitle=Category:Chardok&gcmlimit=500&prop=templates&tllimit=500&format=json
```

Filter the response client-side for pages whose `templates` array contains `Template:Namedmobpage`. Fetch with `curl`/`fetch`, not `WebFetch` — this is exact JSON, and `WebFetch`'s small-model summarization is both unnecessary and risky at this volume (`decisions/eqlwiki-quest-research-method.md` already flags summarization as lossy for exact data).

**Pagination is required, not optional.** `prop=templates` has its own internal limit independent of `gcmlimit`; if the total template-listings across the batch exceed `tllimit`, the response includes a `continue` object (e.g. `{ tlcontinue: "40442|10|Namedmobpage" }`). Merge that into the next request's params and repeat until `continue` is absent — Chardok's 291 category pages took 4 rounds to fully enumerate, narrowing to 151 `Namedmobpage`-tagged candidates.

**Validated, not just assumed:** two of the 151 candidates with NPC-sounding names ("An Imperial Courier", "A droopy slave") were spot-checked with `WebFetch` and both turned out to be real leveled combat mobs (46-47 and 1 respectively) — consistent with migration 145's precedent that `{{Namedmobpage}}` membership alone reliably distinguishes a mob from a vendor/quest-giver/trainer page, even at this scale.

**What this doesn't solve:** the API's `prop=templates` only reports which templates a page transcludes, not the template's own parameters — so it can't hand back each mob's actual level. Getting the level still means fetching each of the 151 pages individually (via `WebFetch`, per the existing method), just against a precise, complete, mechanically-sourced list instead of 287 pages of guesswork. Chardok's own bestiary is still unstarted (issue #36) — this removes the blocker on *which* pages are worth fetching, not the fetching itself.

**Update (Najena/Solusek's Eye/Kedge Keep/Mistmoore Castle batch, issue #36):** the per-page fetch *is* solvable the same mechanical way — `{{Namedmobpage}}`'s `level` (and `zone`) params live in the page's raw wikitext, readable via `action=query&prop=revisions&rvprop=content&rvslots=main&titles=A|B|C|...` batched up to ~20-50 titles per request. A regex pull of `| level = ...` off the returned wikitext gets the exact stated value — no `WebFetch` summarization, no per-page round trip. This finished ~200 mobs across 4 zones in a handful of batch requests instead of ~200 individual `WebFetch` calls. Two things this doesn't remove the need for a human to check:

- **Cross-zone reuse.** A generic name shared across zones (`A Greater Skeleton`, `A Necromancer`) reports a combined `level` string covering every zone it appears in (`"7-20 / 11-13 (Befallen / Najena)"`) — read the `zone` field alongside `level` and pick the segment for the zone actually being sourced, same as migration 184's precedent for Lake Rathetear.
- **Partial/hedged ranges.** `"??-43"` (no lower bound at all) still means excluding the mob, per the existing "An Evil Eye Pet" precedent above — but a hedge alongside two real numbers (`"53?"`, `"18 - 20? (lt blue to lvl 27)"`) doesn't; keep the numeric endpoints as before.
- Worth a spot-check first: confirm a candidate's own `zone` field actually names the target zone before trusting its `level` — one Najena-category page ("A Goblin Warrior") turned out to be miscategorized, with a `zone` field naming two completely different zones instead.

**Update (Permafrost/Splitpaw/Temple of Solusek Ro/The Hole batch, issue #36):** two new edge cases, plus a whole new zone shape:

- **The zone's own map can outrank a mob page's own `zone` field.** Splitpaw's "The Ishva Mal" has a `zone` field naming only South Karana, which would normally mean exclude (per the Lower Guk precedent above) — but Splitpaw's own zone page names it directly in the Map legend, with loot matching its dedicated page exactly, and its description says it "seems likely to spawn at Splitpaw and then runs to the east." When the target zone's *own* page treats a candidate as one of its bosses this concretely, that outweighs a single `zone` field that may just be describing where the mob wanders to, not where it's fought. Contrast with the same batch's excluded "An air elemental" (Splitpaw category): `zone` names only East Commonlands, and — critically — nothing in Splitpaw's own zone page mentions it at all. No corroborating in-zone signal, no inclusion.
- **"Guard"/"Banker"/"Prisoner" flavor names still need a stats check, not a name-based skip.** The Hole's "A ratman guard" and Splitpaw's "Brother Hayle"/"Brother Gruff"/"A Gnoll Prisoner" all sound functional but carry full AC/HP/damage stat blocks and read as real fights (one dungeon-boss-tier at 13,750 HP) — same rule as Runnyeye Citadel's kept "A goblin banker". The name alone is never the signal; the stat block is.
- **A "Quest Only" zone needs its `{{Namedmobpage}}` candidates split by hand, not just filtered by category.** Temple of Solusek Ro's own top table says "Level of Monsters: Quest Only" — every one of its 20 "Inhabitants and Quests" table NPCs (all dialogue-only quest givers) still carries the same `{{Namedmobpage}}` stat-block template as a real mob, because this wiki gives every named NPC that template regardless of role. The category-membership filter that works everywhere else (migration 145 on) doesn't distinguish "has stats" from "is meant to be fought" here — that split has to be read off the zone's own framing and each candidate's own description (a handful of genuine kill-targets, mostly epic-quest fights, were mixed in among the 27 candidates). Future zones this shape (a hub built around quest-giving rather than hunting) need the same manual pass rather than trusting the template filter alone.

**Update (North/West/East Freeport batch, issue #36):** a friendly-race city (Freeport, same shape as North Qeynos before it) buries its real fights inside a roster of named NPCs that all carry full stat blocks regardless of role — so "has stats" still isn't the filter; what actually works is each candidate's own `factions` field (which faction takes a hit when it's killed, i.e. which side it's on). West Freeport's own zone history is a civil war: Sir Lucan D'Lere staged a coup with mercenaries (the "Freeport Militia") and still holds half the city against the loyal Knights of Truth/Priests of Marr. Every one of its ~90 `{{Namedmobpage}}` candidates sorts cleanly along that line: loyalist NPCs (own `factions` = Knights of Truth/Priests of Marr/Guards of Qeynos/Steel Warriors/Arcane Scientists/Ashen Order) are the GM guildmasters and regular "Guard `<name>`" city guards — excluded wholesale, same call as North Qeynos/East Freeport. Militia-occupier NPCs (own `factions` = Freeport Militia/Coalition of Tradefolk Underground/Bloodsabers/Corrupt Qeynos Guards) are a real, designed kill-target roster confirmed by actual weapon/armor drops (Damaged Militia Helm, Rusty/Fine Steel weapons) — including *all 24* of the zone's own "Guard `<name>`" mercenaries, despite sharing the exact naming pattern of the excluded loyalist guards one bullet up. The faction field, not the name, is what tells them apart. Two named exceptions the split alone doesn't catch: "Guard Alayle" reads loyalist by faction but is the actual target of `The Traitor` quest (a double agent planted in the Militia, confirmed by his own drop — the quest's turn-in item); "Knight of Truth" reads loyalist with no quest tie and no distinguishing description — excluded. This same "which faction owns this NPC" check is worth running on any future good-race city zone before defaulting to a wholesale guard/guildmaster exclusion.

**Update (North/South Kaladim batch, issue #36):** the Freeport civil-war split doesn't generalize to every friendly city -- Kaladim (dwarf, no civil war) has just one civic faction line (Storm Guard/Kazon Stormhammer/Clerics of Underfoot/Merchants of Kaladim), yet its guards are still real farm targets, not a wholesale-exclude civic roster like North Qeynos. The tell here wasn't the faction field at all: every one of its 60 `{{Namedmobpage}}` candidates carries both a full stat block *and* non-empty `known_loot` (e.g. Guard Dalammer's Dwarven Axe), and several guards' own descriptions confirm it directly -- Guard Anathur is "sometimes hunted for experience," Guard Cardaff/Humkor/Stump all read "Guards front gate of Kaladim" with combat stats to match. Kept every candidate except "Priest of Discord" (`zone` = Various, the same recurring cross-city service NPC excluded in Felwithe/Neriak). Net rule across all city-zone batches so far: check `known_loot` and any in-description confirmation before defaulting to a wholesale civic-roster exclusion -- North Qeynos's original exclusion (migration 139) predates this method entirely and was never re-verified against it.

**Update (South Qeynos/Qeynos Hills/Qeynos Catacombs batch, issue #36):** two new wrinkles.

- **Guildmasters are excluded, full stop -- CLAUDE.md's rule wins over the "stats over role" pattern.** Kaladim's own shipped bestiary (migration 238) included several `GM <class>` guild-trainer candidates (Gunlok Jure, Datur Nightseer, Priestess Ghalea) under the "stats over role" reading built up across this doc's earlier updates -- but CLAUDE.md is explicit that "guildmasters... don't count," and this batch surfaced 44 more `GM <class>` candidates across South Qeynos and Qeynos Catacombs (level 61, ~20,000-32,344 HP, "None" loot almost without exception, descriptions like "Necromancer guildmaster in the Qeynos sewers"). Per user direction, this batch followed CLAUDE.md literally and excluded all 44, rather than extending Kaladim's precedent further. Kaladim's own guildmaster entries are a known, not-yet-fixed inconsistency -- don't treat them as license to include guildmasters elsewhere. The tell: `class` field containing `GM` (either prefix `GM [[Paladin]]` or, once, suffix `[[Wizard]] GM` -- check both orderings) is a reliable signal distinct from ordinary guards/bankers, which stay included per the rule above.
- **An "active conspiracy" reads differently from a "captured half the city" civil war, but the outcome (keep everyone) is the same.** South Qeynos's guard roster splits cleanly by `factions` into loyalist (Antonius Bayle/Guards of Qeynos) and Commander Kane Bayle's still-secret coup plot (Bloodsabers/Circle of Unseen Hands/Corrupt Qeynos Guards/Kane Bayle) -- structurally like West Freeport's civil war, but Kane's side hasn't taken any territory (his guards patrol alongside loyalists, not in a captured half of the city). Unlike West Freeport, *both* sides carry real stat blocks and confirmed drops (loyalist "Guard Calik" and corrupt "Guard Augos" both drop the same "Rusty Long Sword"), so -- unlike West Freeport's loyalist-wholesale-exclude -- both sides were kept, closer to Kaladim's "check loot, not faction" call than to Freeport's "which faction owns this NPC" split. Worth checking which of these two shapes (captured vs. still-secret) a future civil-war-flavored city actually is before assuming the Freeport split applies.
