# Packed-card hover must brighten via `box-shadow`, not `filter`

`filter: brightness(1.06)` (the same idiom as `.nav-link:hover`/`button:hover` elsewhere in the theme) forces the element onto its own compositing layer, which visibly desyncs a packed card's border from its layout position for a few frames during the hover transition. Brighten through `box-shadow` instead — an inset layer (`inset 0 0 0 999px rgba(255,255,255,0.05)`) on top of the existing two-tone inset bevel — since `box-shadow` paints in the normal flow and doesn't create a stacking context. `filter: brightness()` is still fine for non-packed elements (buttons, nav links).

Card lists (`.zone-card`, `.spell-card`, etc.) previously shared a border with their next sibling via a negative-margin overlap (`margin-top: -4px`), which made this desync worse — see [[card-list-seams-no-border-overlap]] for why that overlap was removed entirely (issue #40). The box-shadow-over-filter rule above still holds independent of that.

Also added, in the same pass: a slow, low-amplitude opacity animation (`body::before`, `torch-flicker` keyframes) on the warm overhead glow, meant to read as ambient torchlight rather than a UI transition. **Removed** (issue #16): the amplitude was low enough that the animation wasn't perceptible in practice, so it was dead weight rather than a visible effect; `body::before`'s static glow stays. Can be re-added later if there's a reason to. And the `.loading` state's text now has a spinning gem above it, reusing `.spell-chip`'s exact gem gradient rather than inventing a new spinner glyph — "the page is casting," not a generic loading spinner.
