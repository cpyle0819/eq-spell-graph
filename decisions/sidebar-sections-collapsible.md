# Sidebar sections are collapsible, and reuse the `[hidden]` fix from Class Browser's Spell Line bug

Each `.field-group-label` header is now also a click/keyboard toggle for the fields under it (`SidebarPanel`'s `sectionHeader()` in `components.js`, wiring in `app.js`'s `setupCollapsibleSections()`). Toggling sets a `.field`'s native `hidden` property — which only actually hides anything because of the `.field[hidden] { display: none; }` fix added for the "Class Browser Spell Line field stays visible" bug; without that fix this feature would have silently done nothing, same as that bug.

**A `role="button"` div, not a real `<button>`.** `button { ... }` in theme.css is a heavy bone-plate style (padding, gradient, border, box-shadow, uppercase) meant for real actions like Reset/Show all — turning a `.field-group-label` into a `<button>` would either inherit that look wholesale or need a pile of resets to strip it back down. A `div` with `role="button" tabindex="0"` plus manual `click`/`keydown` (Enter/Space) handlers gets the interaction semantics without any of that fight. The expand/collapse indicator is a `::before` chevron keyed off `aria-expanded`, not JS-written text — one attribute flip drives both the fields' visibility and the icon, so they can't drift out of sync.

**Only Spells starts open** (`DEFAULT_COLLAPSED_SECTIONS` in `app.js`) — picking which spells to look for is the page's actual job; Faction, Level, and Location are all secondary narrowing/config concerns you dip into as needed rather than every visit. (An earlier pass left Level open too, alongside Spells, before being tightened to just Spells.)

**Reset filters also resets collapse state, not just filter values** — `applyDefaults()` (called both for a first-time visitor and by `resetFilters()`) unconditionally sets all four sections to their default collapsed/expanded state, not just the two that default closed. An earlier version only forced Faction/Location closed and left Spells/Level's collapse state untouched, which meant Reset filters gave a partially-reset sidebar if you'd manually collapsed Spells or Level — inconsistent with Reset's documented "restores every filter to its out-of-the-box default" behavior.

Collapse state persists in the same `localStorage` blob as the rest of planner state (`collapsedSections: string[]` in `getState()`/`restoreState()`), not a separate key — it's small and there's no reason to manage its lifecycle independently of everything else that's already saved together.

**`.field-group-label`'s first version had the hierarchy backwards** — 10px, 0.75 opacity, no text-shadow, versus `.field label`'s 11px/full-opacity/shadowed — making the section headings the *least* legible text in the panel, reported back as "hard to read." Fixed by making it unambiguously the more prominent of the two: 13px, bold, `--parchment` colored, same text-shadow formula `.field label` uses for legibility against the marble turbulence texture. Computed exact contrast ratios before picking the color rather than guessing — `--gold` (3.65:1) and `--gold-bright` (4.37:1) both measure under this app's own 4.5:1 AA bar for small text against `--stone-1`, despite `--gold` reading fine elsewhere on this same marble (e.g. `.zone-route .route-sep`, which is much larger); `--parchment` (6.03:1) was the established stone-panel body-text color already comfortably clearing it.
