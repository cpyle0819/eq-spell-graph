# Quest structure and reward modeling

`quest` node shape: `label`, `description`, `classes` (empty/absent = anyone, same "no selection = all" convention as elsewhere), `minLevel`/`maxLevel` (each independently optional; absent = no bound in that direction), `steps` (plain ordered array of strings — a step has no identity beyond belonging to this quest, so it's not its own node type), `total_experience` (the quest's whole XP total, tracked as one flat number even if individual steps notionally reward XP along the way — no per-step breakdown).

Item and faction rewards are edges, not fields — a quest can have any number of them:

- `quest --rewards--> item`
- `quest --rewards--> faction`

One `rewards` edge type covers both; the target node's own `type` disambiguates which kind of reward it is, rather than splitting into `rewards_item`/`rewards_faction`. Reasoning: items and factions are real entities (things other quests/vendors could eventually also point at), so they get the same edges-not-fields treatment as `sells`/`located_in`; experience isn't an entity, so it stays a scalar field. No quantity/amount attribute on `rewards` edges yet (e.g. "3x Sturdy Ore Sack" or "+250 faction") — deferred until real data needs it, same way `connects_to` only grew a `transport` attribute when boats/translocators required one.

Quest location and quest giver are also edges: `npc --starts--> quest`, and `quest --located_in--> zone` / `quest --starts_in--> zone`. A quest can have more than one `starts`, `located_in`, or `starts_in` edge for free if a real quest needs multiple quest-givers or spans multiple zones.

**`located_in` vs `starts_in` (as of the Estate of Unrest quest batch)**: originally `located_in` meant only the giver's zone, one-for-one with `npc --located_in--> zone`; mid-quest farming/turn-in stops in other zones stayed prose-only in `steps` (migration 034's rule). That undercounted real zone involvement — a quest requiring a reagent found in a given zone (e.g. Harvester Quest's Fungus Eye, on Mortuary Fungus in The Estate of Unrest) genuinely touches that zone, and a zone's own Quests tab should surface it so a player browsing that zone sees quests they might already be gathering for. So `located_in` on a quest is now the broader claim — every zone a step sends the player to for a required item or sub-turn-in — and `starts_in` is the new, narrower edge (source: quest, target: zone) for specifically where the quest begins, feeding the Quests UI's "Starts In" card section.

The broadened `located_in` intentionally does **not** require a zone to be the *only* source for an item — a first pass restricted it to sole-sourced reagents only (skipping Totemic Armor Quests' Estate-of-Unrest tie because Terror Spines also drops in Najena), but that missed the actual goal: surfacing "you could pick this up here," not just "you're forced to come here." A zone gets a `located_in` edge whenever the wiki's own "drops from" listing for a required item names it, full stop — whether or not other zones also work. Purchased-for-coin components whose vendor's zone isn't stated on the quest page don't get chased down just to fill this in (disproportionate research for one migration entry); those stay prose only.

`getQuests(zoneId)`/`getQuestGroups(zoneId)` match a zone against either edge type, so a quest one-and-done in a single zone can just carry `located_in` (as before) while a quest that spans zones adds `starts_in` for its actual starting point plus `located_in` for every zone a step touches (giver's zone included, since it's also "touched").

**No backfill**: quests added before this batch keep only their original `located_in` edge (still correct — for them it always was the giver's zone) and get no `starts_in` edge. `buildQuestSummary` (`src/graph.ts`) falls back to `located_in` for the "Starts In" display when a quest has no `starts_in` edges, so old quests render unchanged. New quests going forward should add `starts_in` whenever a real farming/turn-in stop also earns a `located_in` edge, so "Starts In" doesn't misleadingly list every zone a quest touches.
