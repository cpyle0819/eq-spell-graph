# Home page: tool buttons are a touching macro-socket grid, no per-tool description text, positioned left of the welcome scroll

`tool-card.js` (the stone-panel wrapper pairing each tool's `<macro-button square>` with a slotted description `<p>`) is gone — deleted, not deprecated, and its import dropped from `public/components/index.js`. Each `macro-button` is already its own full beveled cavity (`.macro-socket`, `:host` in `public/components/macro-button.js` — see `decisions/macro-button-shared-component.md`), so wrapping it in a second bordered panel was redundant once the description text it existed to hold went away.

`home.html`'s `.tool-grid` now holds the four `<macro-button square>` elements directly, packed into a 2×2 `inline-grid` (sized to its four 90×90 sockets, not stretched full-width) using the same shared-seam technique as `zone-card`/`spell-card` elsewhere (`decisions/packed-card-hover-box-shadow-not-filter.md`): `margin-left: -5px` on the second column, `margin-top: -5px` on the second row — 5px matching `.macro-socket`'s own `border-width` when `square`, so the overlap fully absorbs into one shared bevel rather than doubling it. Paint order (later DOM siblings on top) is what makes the seam clean, same as the existing vertical-only uses of this trick; here it's extended to both axes since the grid is 2D.

Layout: `main` is a column flexbox (`welcome-scroll` first in DOM, `.tool-grid` second) so narrow/stacked layouts read intro-first, buttons-second — unchanged from before. At `min-width: 761px` (matching this app's existing 760px breakpoint elsewhere), `main` switches to `flex-direction: row-reverse`, which visually flips the *same* DOM order to grid-left, scroll-right without duplicating markup, adding a JS-driven reorder, or touching the stacked mobile order at all. No separate mobile-specific tool-grid layout was needed: the grid's `inline-grid` sizing keeps its four-socket cluster small and fixed-size (unlike the old text-card grid, which needed `grid-template-columns: 1fr` on mobile to keep description text readable), so it drops cleanly under the scroll at any width below the breakpoint without its own breakpoint logic.
