# `graph.json` nodes/edges are flat objects, not `{data:{...}}`

Through migration 283, every node/edge in `data/graph.json` was wrapped as `{ data: {...} }` — the Cytoscape.js elements format, needed because the app fed the raw file straight into a Cytoscape graph-view tab (`cy.add()`/`cy.json()` expect exactly that shape). That tab was removed by the "Redesign UI" rewrite (commit `21f40c9`, 2026-07-02) and never came back — nothing in `public/` references Cytoscape since, and `package.json`'s `cytoscape`/`@types/cytoscape` deps had gone unused ever since without anyone noticing. `/api/graph` (which returns `getGraph()` raw) is likewise dead — no frontend code calls it.

With the visualization gone, the wrapper was pure overhead: every one of `src/graph.ts`'s ~30 read functions paid an extra `.data` hop on every node/edge access for a format contract nothing checked anymore. Migration 284 flattened it — `{ nodes: [{data:{id,...}}] }` → `{ nodes: [{id,...}] }`, same for edges — and `src/graph.ts`/`src/api.ts` were updated to match. `migrations/_lib.ts`'s `loadGraph()` helper (used by migrations written after 284) assumes the flat shape too; migrations before 284 keep their own now-historical `{data:{...}}`-shaped code untouched, per the usual "migrations are a run-once record, never edited after the fact" rule.

Same pass folded `rankZones()`'s own narrow edge index (`getIndex()`: `sellsByTarget`/`locatedInBySource`/`lineBySpell`, keyed by hand) into the general-purpose `graphIndexHelpers()` every other hot path already used — `getIndex()` predated `graphIndexHelpers()` and never got consolidated once the general one existed. There is now exactly one edge index in this codebase, built as a set of `Map`s in memory the first time a request needs it per process and cached for that process's lifetime (invalidated by `save()`); it is deliberately *not* persisted to `graph.json`. A stored index would be strictly worse: `Map` isn't JSON-serializable, so persisting it wouldn't save the O(E) build cost, it'd just move that same cost to a second file's load-and-reconstruct step, and the ~280 files under `migrations/` write `graph.json` directly rather than through `src/graph.ts` — a persisted index would go stale the instant any of them forgot to regenerate it, with no mechanism forcing a rebuild the way the in-memory cache self-invalidates every fresh process.
