# Primary Class also has an "Any (ignore faction)" option; all three faction fields now default to Any

Primary Class was the odd one out — Race and Deity both had `any`, Primary Class didn't. Added `<option value="any">` (last, same convention as above) and a matching `classIgnored` on `ZoneRanking`/`rankZones()` (`src/graph.ts`), mirroring `raceIgnored`/`deityIgnored`: substitutes `"safe"` for `classStanding` in the worst-of computation, only neutralizing its own dimension — a real class-driven wont_sell/kos still shows through when race/deity are Any (and vice versa), confirmed by setting `primaryClass=necromancer` with race/deity at Any and seeing "18 zone(s) won't sell to you" persist. The results-header note now lists any/all of "race, class & deity ignored" rather than just the two.

Once Primary Class could be Any, the actual defaults changed too: Race/Primary Class/Deity now all ship `selected` on their `any` option, replacing the old Barbarian/Shaman/The Tribunal starting point (`resetFilters()`'s hardcoded values updated to match). Rationale: these three fields only affect vendor faction standing, not which spells show up (see the sidebar's "Faction" section tooltip) — defaulting to three arbitrary specific values suggested they mattered more than they do, and silently applied someone else's faction profile to every fresh visitor. Any *existing* visitor's `localStorage`-persisted state is untouched by this — `restoreState()` still wins over `applyDefaults()` when present, so this only changes what a first-time visitor (or someone who clicks Reset filters) sees.
