# npc/mob unification and zone-type-ordered groups

A user compared Maps' three separate "level" displays for the same zone (the dossier's mocked level badge, route-card's vendor-derived range, the bestiary's mob levels — see [zone-level-badge-retired-mock-data.md](zone-level-badge-retired-mock-data.md)) and, while fixing that, asked a related question: is it right that vendors/guards/guildmasters/quest-givers/creatures are all `npc` nodes? They weren't — `mob` (creatures, and city guards per the precedents in [mob-node-type.md](mob-node-type.md)) was a separate node type from `npc` (vendors/quest-givers only). That split had no room for "guard" as its own concept and forced Maps' Bestiary into one flat mob-only roster with no way to show a zone's civic roster (guildmasters, vendors) alongside it.

**New paradigm: every entity is an `npc`.** Migration 265 retired `mob` as a `type` value entirely. What used to be the type discriminator is now the `roles` array (already existed for vendor/quest_giver — see `addNpc`/`addGiver` in `migrations/_lib.ts`), expanded to five values: `vendor`, `quest_giver`, `guard`, `guildmaster`, `mob`. An npc can carry more than one role (a named guard who also gives a quest); callers render it once per matching group, not once overall — see `npcGroupsHtml()` in `public/components/zone-dossier.js`.

Role assignment for a former mob node: `guard` if its label matches `/^(A |An )?Guard /`, else `mob`, with one hardcoded exception — the 3 Kaladim guildmasters (Gunlok Jure, Datur Nightseer, Priestess Ghalea), whose names carry no detectable pattern distinguishing them from any other named mob.

## The 206 duplicates

Merging wasn't a clean type-flip. eqlwiki.com tags *every* named page with its combat-stat template regardless of role (already noted in mob-node-type.md's own East Freeport/Kaladim updates), so a zone's `{{Namedmobpage}}` category routinely includes NPCs that already exist in the graph as a quest-giver or vendor. Earlier bestiary migrations (060 on) didn't check for this — they added a second node under a `mob:<zone>:<slug>` id even when `npc:<zone>:<slug>` already existed for the exact same character. 206 such pairs existed graph-wide (e.g. `npc:east-cabilis:grand-master-glox` a quest-giver, `mob:east-cabilis:grand-master-glox` the same person with level/combat stats) — confirmed via id-suffix matching across every mob node. The Kaladim guildmaster "known, not-yet-fixed inconsistency" mob-node-type.md already flagged turned out to be exactly this bug, not a special case.

Every mob node's only edge was ever its own `located_in` (nothing else references a mob id — no drops/loot links exist per mob-node-type.md's own "out of scope" note), so migration 265 merges each duplicate pair by unioning `roles` and copying `minLevel`/`maxLevel` onto the existing npc node, then deletes the now-redundant mob node and its edge. Nothing was lost. The remaining ~3,087 mob nodes with no npc counterpart just convert in place.

This pass was schema/UI restructuring of data already in the graph — it does **not** backfill the guildmasters/guards that earlier batches deliberately excluded from other city zones (North Qeynos, Freeport, etc., per mob-node-type.md's own exclusion rule). That stays a separate future eqlwiki-sourcing pass, same shape as the issue #36 batches, now that Guildmaster/Guard are real displayed groups worth having complete.

## Zone types and group order

Migration 266 adds `zoneType: "city" | "dungeon" | "open_world"` to every zone node — a new key, not a reuse of the existing `type: "zone"` node-type discriminator (same naming collision this doc's own `roles`-not-`type` choice above avoids for npcs). Classified from each zone's own `lore` text plus standard EverQuest zone knowledge; see the migration's own header comment for the handful of genuine judgment calls (Kael Drakkal/Thurgadin/Icewell Keep read as a hostile faction's turf but are still literally called a city in their own lore, so kept as `city`; the four Planes are hostile instance-like zones with no literal walls, kept as `dungeon`).

Group display order (`public/components/zone-dossier.js`'s `CITY_ROLE_ORDER`/`DUNGEON_ROLE_ORDER`): `city`/`open_world` render `Guildmasters, Vendors, Quest Givers, Guards, Mobs` — open-world "cities" like Kelethin aren't treated any differently, since the two zone types behave identically here. `dungeon` is the exact reverse: `Mobs, Guards, Quest Givers, Vendors, Guildmasters`, since a dungeon visitor came for the hostile roster first. A zone with no npcs in a given role simply doesn't render that group — no empty-state placeholder per group, only a single "No npcs catalogued yet" message if every group is empty.
