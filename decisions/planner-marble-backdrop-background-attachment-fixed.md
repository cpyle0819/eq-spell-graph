# `#planner`'s marble backdrop needs `background-attachment: fixed`

On wide layouts `#planner` uses `overflow: visible` (needed so `.controls-panel`/`.status-panel` can `position: sticky` against it) rather than clipping and scrolling its own content — confirmed via `window.scrollY` vs. `#results`'s own `scrollTop` while scrolling that the *document* is what actually scrolls in that layout, not an inner `#results` container (its `overflow-y: auto` is a no-op there since its content is never taller than itself). That meant `#planner`'s own `background` (marble texture + lit-top/shaded-bottom gradient, default `attachment: scroll`) moved right along with the document scroll — visibly sliding as you scrolled, since it's repainted at the document's coordinates, not the viewport's. Fixed by setting `background-attachment: fixed` on just the marble-texture layer (`background-attachment: fixed, scroll` — the two values map to the two comma-separated images in `background:`), leaving the lit-top/shaded-bottom gradient tracking `#planner`'s own box as before, since that's shading one specific panel's real top/bottom edges, not something that should repeat every viewport height. `.zone-card`/`.controls-panel`/`.status-panel` keep default-attachment backgrounds on purpose — each is a physical object that should carry its own surface with it, unlike the backdrop behind/between them. Separately: no, `.zone-card` instances don't share one continuous painted background — each tiles the same marble texture independently from its own box origin. Not fixed, since it's a random turbulence noise pattern (translation-invariant-looking), so the seam between packed cards shows no visible discontinuity in practice.
