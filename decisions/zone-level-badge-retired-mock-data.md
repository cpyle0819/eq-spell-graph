# Zone level badge: retired the mock, and dropped route-card's second one

Maps' zone dossier originally showed a "Levels X–Y" badge next to the map name driven by `public/zone-mock-data.js`'s `mockLevelRange()` — a deterministic hash of the zone's *label string*, invented as a stage-1 UX placeholder before any real per-zone level data existed (see `decisions/mob-node-type.md` for the same origin story on the Bestiary section itself). The mock's own header said to delete it "once a real zone level range is sourced and wired through src/graph.ts instead." Mob data (`getMobs()`) did land for other reasons and nobody circled back — the mock quietly kept rendering fabricated numbers indefinitely, alongside two *real* but differently-scoped level numbers: route-card's vendor-derived `levelRange` (`getZoneVendorInfo` in `src/graph.ts`, spanning every `class_levels` entry across every spell any vendor in the zone sells — a spell-shopping range, not a danger judgment) and the bestiary's own per-mob levels. A user spotted the mismatch: none of the three agreed, because one of them wasn't measuring anything.

Fix: `maps.js` now computes the dossier's `levelRange` itself, client-side, as a min/max reduction over the same `mobs` array it already fetches from `/api/mobs?zone=` (`mobsLevelRange()`) — a real fact about the zone's bestiary, `null` when a zone has no mobs catalogued yet (same "unknown" shape `getZoneVendorInfo`'s own `levelRange` already uses). `zone-mock-data.js` is deleted.

Separately, route-card's own "N vendors · Lvl X–Y" badge was cut entirely (down to just the hop-count badge) rather than relabeled — even a correctly-labeled "spells sold here span levels X–Y" would still sit right next to the dossier's bestiary-derived level badge below it, and two differently-scoped numbers both called "level" in the same view reads as a bug even when both are individually accurate. One zone, one level answer (the bestiary), shown once, in the dossier.

**Rule going forward:** never invent a placeholder value for a real-world fact, even temporarily — a mock with no wiring back to real data has no way to signal it's gone stale, and nothing forced anyone to revisit it once real data existed elsewhere for a related field. And when two derived numbers legitimately measure different concepts (shopping-level vs. danger-level here), don't surface both as unlabeled "level" badges in the same view — pick the one the view is actually about, or label both unmistakably.
