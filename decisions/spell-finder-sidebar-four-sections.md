# Vendors sidebar is grouped into five labeled sections: Location, Level, Faction, Travel, Shopping For

**Superseded (Vendors/Type filter, see decisions/vendors-type-filter.md) — order was originally Faction → Spells → Level → Location, all four always visible.** Adding a Type filter (spells vs. vendor-sold item categories) meant Level could no longer always apply — items carry no per-class level data the way spells do — so it had to become conditionally hidden based on something inside what was then the "Spells" section. Rather than have a bottom section's state reach up and hide a section above it, the four filters that stay meaningful regardless of Type (Location, Level, Faction, Travel — Travel split out of Location into its own section at the same time) moved to the top, and "what am I actually shopping for" (Type, Class, and Type-specific fields) became its own section, "Shopping For," at the bottom. Level itself still lives near the top positionally, but is hidden via `[hidden]` whenever Type isn't Spells — visually it's grouped with the top four, but its visibility is still driven by the bottom section's own Type control.

Each group is a `<collapsible-section>` (public/components/collapsible-section.js — see decisions/real-web-components-shadow-dom.md), closed off by a `.control-sep` divider, same ornamental divider that used to just sit once between the Race/Primary Class/Deity trio and everything else.

Only the Faction group's label carries a `section-title` tooltip ("Race, Primary Class, and Deity only affect vendor faction standing — they don't filter which goods show up below") — that's the one dimension genuinely confusable with a results filter (a plausible first guess is "picking a race narrows which spells I see"), so it needed an explanation, not just a name. The others are self-explanatory groupings and don't need one — `.header[title]` is the only selector that gets `cursor: help`, so they don't visually promise an explanation they don't have.

Only Shopping For starts open — picking what to shop for is the page's actual job, everything else is a secondary narrowing/config concern. See decisions/sidebar-sections-collapsible.md for the collapse mechanics themselves (note: that doc predates the collapsible-section Web Component and describes an earlier `.field-group-label`/`SidebarPanel.sectionHeader()` implementation of the same idea).
