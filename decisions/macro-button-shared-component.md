# MacroButton: one shared component for every non-text button, socket + raised button, two bevels

Modeled on the reference client's bottom-left macro bar (assets-cdn.daybreakgames.com/uploads/dcsclient/000/000/108/481.jpg and a user-supplied crop, `~/Downloads/ui_buttons.png`), replacing both the old floating bone-plate `.nav-link` style and the first pass at a status-panel-only square button. `public/components.js` exports `MacroButton({ label, tag, href, id, className, square })`, returning a `.macro-socket` (recessed cavity) wrapping a `.macro-btn` (raised button or link) — every non-text button on every page renders through this one function: nav links (`tag: "a"`) and the status panel's Show all/Show remaining/Clear owned. `.text-action` (plain muted links like Reset filters, or the empty-results "Show all" fallback) is a separate idiom and doesn't use it.

Sizing: dynamic (fits the label) by default, since nav labels vary in length; pass `square: true` for a fixed 90×90 slot instead, e.g. the two status-panel actions sitting side by side, where they need to match each other's size regardless of label length. Both `.macro-socket`/`.macro-btn` use *pixel* dimensions when square (not `aspect-ratio`/`flex-grow`, which content can still push around) — labels over 10 characters get a `.long-label` font-size reduction instead, so the box size never changes, only the text does.

Light source is top-right for this whole component: the raised `.macro-btn` catches light top+right and shadows bottom+left; the recessed `.macro-socket` is the inverse — dark top+right (`#362c5a`), lit bottom+left (`--edge-hi`). The socket's inset shadows use blur (not 0-blur offsets) so the bevel actually sweeps around its `border-radius` instead of looking clipped at the corner.

**This was originally a deliberate exception** to a top-left convention `.zone-card`/`.controls-panel` used elsewhere — later reversed (see "Whole-app light-source consistency pass" below): MacroButton/MacroSocket turned out to be the one component already built correctly, and everything else got flipped to match it instead.

The button's own bevel is a second, independent effect on top of the socket's: `::before`/`::after` pseudo-elements painted with `mix-blend-mode: lighten`/`darken` (not fixed overlay colors) so it reads as brightening/dimming the button's actual gradient rather than painting a flat tint over it. Each fades from the button's own color back to white/black over 5px (6px for `.square`, since a bigger surface reads better with a slightly heavier bevel). `clip-path` confines each pseudo-element to an L-shaped region (its own two edges) so the light and dark bevels meet with a clean 45° miter at the corners, rather than the two independent per-edge gradients overlapping as a rectangle. `--bone-tex` (the marble turbulence recipe, reused at a different alpha) is layered into both the button face and the bevel pseudo-elements themselves, so neither is a mathematically perfect gradient — it's faintly mottled, matching the marble panels' own texture treatment.

`--bone-1`/`--bone-2`/`--bone-edge-hi` (the shared bone-plate face colors) were also lightened slightly toward white as part of this pass — a site-wide token change affecting every bone-plate surface.

**`pressed` vs. `toggled`:** `pressed` renders as an inert `<span>` (current-nav-page — nothing to click your way out of). A later real on/off control (Maps' Include Wizard Port button) needed the same depressed look but had to stay a clickable `<button>` in both states, so `toggled` was added as a separate attribute: same `.pressed` CSS class, but the element stays a real `<button>` with `aria-pressed`. Don't reuse `pressed` for anything the user needs to un-press by clicking it again.
