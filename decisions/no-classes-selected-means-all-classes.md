# No classes selected means "all classes," not "pick one"

`fetchAbilities()` used to bail out entirely when all three class pickers were set to "— None —," showing a "Pick at least one class" placeholder and leaving the previous class selection's fetched data (`rawSpells`/`rawStances`/etc.) sitting in memory unrefreshed — so typing into Search while on "— None —" silently searched whatever class had been selected *before*, not "no filter," which read as a stale/broken result. Removed that early return: an empty class selection now always fetches, with `class=` sent empty, and `/api/spells` (`src/api.ts`) was changed to match `/api/stances-invocations`/`/api/aa`'s existing "empty classNames = every class" convention instead of silently defaulting to `shaman` (a leftover default nothing else relied on — `getSpellsForClass` per-class calls are unioned via `getAllSpells()` in `src/graph.ts` when no class is given). The three-`<select>` picker this was originally written against is gone (see "Sidebar filter panel" below) but the underlying convention — empty selection = every class — still holds for its replacement tag box.
